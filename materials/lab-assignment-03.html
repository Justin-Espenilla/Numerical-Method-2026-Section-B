Downhill in the Fog

Build gradient descent from the derivative up, map its stability limit experimentally, defeat a narrow valley, and use it to fit a nonlinear model to laboratory data.

Part A — The engine 20 pts

  1. Implement gradient(func, x, rel_h) by scaled centred differences, and gradient_descent(func, x0, alpha, tol, max_iter) returning (x, f, n_iter, history). Stop on |∇f| < tol, cap the iterations, and raise a clear error on divergence.
  2. Validate the gradient before you trust the optimiser. For f(x) = 3x12 + x1x2 + 2x22, derive ∇f by hand and compare it to your numerical gradient at three different points. Report the agreement to how many significant figures. A wrong gradient produces a confidently wrong optimum, so this check is worth its marks.
  3. Minimise the bowl f = (x1−3)2 + 2(x2+1)2 from (0, 0). Report the minimiser, the minimum, the iteration count, and the final |∇f|.

Part B — The stability limit 25 pts

  1. For the bowl, run descent for α = 0.05, 0.1, 0.2, 0.3, 0.4, 0.45, 0.49, 0.51, 0.6. Tabulate: iterations to converge, or "diverged" with the iteration at which it blew up.
  2. Find the critical α to three decimal places by bisecting on α itself — reuse the bracketing idea: converged on one side, diverged on the other.
  3. Compute the Hessian of the bowl by hand, find λmax, and compare 2/λmax with your measured critical α. Comment on the agreement.
  4. Repeat the whole exercise for f = (x1−3)2 + c(x2+1)2 with c = 1, 5, 20, 100. Plot the measured critical α against c on log-log axes and confirm the predicted relationship.
  5. For c = 100, plot the iterate path over a contour map. Describe what the condition number λmax/λmin is doing to the path, in two sentences.

Part C — Defeating the valley 25 pts

Use the Rosenbrock function, starting from (−1.2, 1.0), tolerance 10−5, cap of 50,000 iterations.

  1. Run plain fixed-step descent. Tune α as well as you can and report the best result you achieve — including an honest "did not converge" if that is what happens.
  2. Add backtracking line search (Armijo). Report iterations, function evaluations, and the final point.
  3. Add momentum with β = 0.9. Report the same three numbers.
  4. Present all three on one semilog-y plot of f against iteration, plus one contour-with-path figure per method.
  5. Count function evaluations, not just iterations — backtracking spends extra evaluations inside each step. Which method wins on total evaluations? Is that the same winner as on iteration count? Discuss in one paragraph.
Where marks are lost in Part C

Reporting iteration counts as if they were cost. An iteration of backtracking can cost ten function evaluations. In real engineering optimisation the function evaluation is the cost — everything else is bookkeeping. Instrument your code with a counter.

Part D — Fitting a real model 15 pts

Generate your creep-test data with seed = the last two digits of your student number:

def creep_data(seed):
    rng = np.random.default_rng(seed)
    t   = np.linspace(0.5, 40, 40)                 # hours
    a_true, b_true = 0.0085, 9.4                  # do not use these in your fit
    eps = a_true*(1 - np.exp(-t/b_true))
    eps += rng.normal(0, 1.5e-4, t.size)
    return t, eps
  1. Fit ε(t) = a(1 − e−t/b) by minimising the sum of squared residuals with your optimiser. Report a, b, and the final SSE.
  2. Scaling matters here. a is of order 0.01 and b is of order 10 — a ratio of a thousand. Run the fit once unscaled and once with each parameter divided by its nominal magnitude. Report both outcomes and explain the difference.
  3. Plot the data with your fitted curve, and a residual plot beneath it. Comment on whether the residuals look random or structured, and what structure would mean.
  4. Restart from four different initial guesses spanning an order of magnitude. Do they all reach the same minimum? Report the table and state whether this landscape appears convex.
  5. Using Lab 02's method, compute the dimensionless sensitivity of the SSE to each fitted parameter at the optimum. Which parameter is your data actually pinning down, and which is loosely constrained?

Part E — AI Prompt Log 15 pts

Required prompt experiment — the tempting shortcut

Ask an AI assistant:

fit epsilon = a*(1-exp(-t/b)) to my data in python

It will almost certainly hand you scipy.optimize.curve_fit. That is the correct professional answer and the wrong answer for this assignment. In your log:

  1. Run its curve_fit solution anyway and record the parameters it produces.
  2. Compare them to your own gradient-descent parameters. Report the difference in a, b, and SSE.
  3. If your numbers disagree with SciPy's by more than 1 %, your optimiser has not converged — go back and fix it, and document what was wrong. This is the log entry that earns the most credit in this assignment.
  4. Write a second prompt that forbids external optimisers and demands the update rule be written explicitly. Compare the two outputs and note anything the second one got wrong.
  5. In three sentences: when is reaching for curve_fit the right engineering decision, and when does it leave you unable to defend your own result?
