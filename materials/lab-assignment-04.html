Part A — Three rules, three orders 30 pts

  1. Implement left_rect, trapezoid, and simpson for a callable f on [a, b] with n strips. Simpson must reject odd n with a clear error.
  2. Test integral:
    I = ∫02 ( x3 − 3x + 2e−x ) dx
    Compute the exact value analytically by hand and show the work.
  3. Produce an error-ratio table for each rule at n = 4, 8, 16, 32, 64, 128, 256. Columns: n, estimate, |error|, ratio to the previous error.
  4. State the limit each ratio column approaches, and confirm it equals 2p for the order p of that rule. Any column that does not converge to its expected value indicates a bug — fix it before submitting.
  5. Plot all three error curves against h on log-log axes. Fit and report the measured slope of each to two decimals.

Part B — How you add up the strips 20 pts

Refining the subdivision reduces truncation error and increases the number of additions. This part locates the point where the second effect overtakes the first — and shows that where it happens depends on how the addition is done.

  1. Implement the trapezoidal rule three ways, differing only in how the strips are summed:
    1. a plain Python for loop with a running total;
    2. np.sum;
    3. math.fsum.
  2. For n from 102 to 106, log-spaced, tabulate the error of all three and plot them together on log-log axes.
  3. One of the three stops improving and then gets worse. Identify which, report the n at which it bottoms out and the floor it reaches, and explain the mechanism in terms of the number of additions and the size of machine epsilon.
  4. The other two keep improving to the end of the range. Investigate why, and name the summation algorithm NumPy uses. State what this implies about the common claim that "more strips eventually makes numerical integration worse".
  5. Repeat for Simpson's rule with np.sum. Report the n at which it reaches machine precision, and the factor by which that is fewer evaluations than the trapezoid needs for its best result. State the practical lesson in one sentence.

Part C — The storm audit 30 pts

Generate the rain-gauge record with seed = the last two digits of your student number. Note the two missing samples — the logger dropped them, exactly as tipping-bucket gauges do.

import numpy as np

def storm_record(seed):
    """Rainfall intensity at a municipal gauge. t in hours, i in mm/h."""
    rng = np.random.default_rng(seed)
    t = np.arange(0, 6.0001, 1/12)                              # hours, every 5 min
    i = 2 + 46*np.exp(-((t - 2.6)/0.9)**2) \
          + 12*np.exp(-((t - 4.4)/0.5)**2)                    # mm/h
    i = np.maximum(i + rng.normal(0, 1.2, t.size), 0)
    keep = np.ones(t.size, bool); keep[[17, 44]] = False       # dropped samples
    return t[keep], i[keep]
  1. Plot the intensity hyetograph against time. Mark the two gaps.
  2. Compute the total rainfall depth with your unequal-spacing trapezoid rule. Report it in millimetres to a defensible number of significant figures, and justify that number.
  3. Compute the same total the way the original analyst did — average of the first and last reading times the duration. Report the discrepancy in millimetres and in percent. The contributing catchment is 42 hectares; express the discrepancy as a volume in cubic metres of runoff, assuming a runoff coefficient of 0.65.
  4. Apply Simpson's rule. Since the samples are unequally spaced you must handle the gaps: state your strategy (segment-wise Simpson, or Simpson plus a trapezoid for the odd strip) and implement it. Compare with the trapezoid total.
  5. Plot the cumulative rainfall on the same time axis as the intensity. Report the depth accumulated by hour 2, hour 3 and hour 5. Confirm that the mass curve is steepest where the intensity peaks.
  6. Close the loop with Lab 1. Differentiate your cumulative curve numerically and overlay it on the original intensity data. Report the maximum discrepancy and state what the fundamental theorem of calculus predicts here.
  7. The gauge carries ±1.2 mm/h of random noise. Estimate the resulting uncertainty in the six-hour total and state whether it is large or small compared with the discrepancy in step 3. Write one paragraph on what this says about integrating noisy data versus differentiating it.
Where marks are lost in Part C

Using np.trapz or scipy.integrate for the answer. You may use them only as a cross-check, and you must say so. The assignment asks you to build the rule; a library call proves nothing about your understanding of it.

Part D — AI Prompt Log 20 pts

Required prompt experiment — the unequal-spacing trap

Ask an AI assistant:

write a python function for simpson's rule

Then, in your log, test its output against the following specific cases and record what happens:

  1. An odd number of strips. Does it error, silently give a wrong answer, or handle it?
  2. Unequally spaced data like your storm record. Most implementations assume constant h. Feed it your real timestamps and quantify how wrong the answer is.
  3. Compare its result on your storm data against your own segment-wise implementation. Report both numbers.

Then write a strong prompt that states the spacing may be unequal, the sample count may be even or odd, and the fallback strategy required. Compare the two outputs, and state one thing the second one still gets wrong or handles awkwardly.

Close with two sentences: what class of bug does a generic AI answer produce when your data does not match its unstated assumptions, and how would you catch it in future?
