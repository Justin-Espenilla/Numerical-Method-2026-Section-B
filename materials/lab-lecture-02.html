Sensitivity Analysis — Which Number Should You Worry About?

Every design calculation has half a dozen inputs and every one of them is uncertain. The derivative tells you which uncertainties matter and which you can ignore. This is the most commercially valuable use of calculus you will learn all semester, and it is the same finite difference you wrote in Lab 01.

1. The story: the argument in the design review

Case file — consulting office, pump station design review

Two engineers are arguing about a budget. The design needs a head-loss calculation, and there is money for exactly one more site measurement.

One wants to re-survey the pipe length — "we only paced it out." The other wants a proper roughness test — "the friction factor is a guess from a table." Both are right that their number is uncertain. Only one of them is right that it matters.

The senior engineer settles it in ninety seconds with a spreadsheet. She perturbs each input by one percent and writes down how much the answer moves. Pipe length: the answer shifts 1 %. Diameter: the answer shifts 5 %. She sends the crew to measure the diameter — which neither of them had proposed.

What she actually computed

A partial derivative, evaluated numerically. Sensitivity analysis is not a separate technique — it is the physical meaning of the derivative applied to a design instead of to a moving object. Slope becomes "how much does the output move when this input moves."

2. From one variable to many

Your Lab 01 differentiator handled f(x). A design calculation is f(x1, x2, …, xn). The partial derivative asks: nudge input j, freeze everything else, watch the output.

∂f ∂xj ≈ f(…, xj+h, …) − f(…, xj−h, …) 2h

That is the centred difference from Lab 01, applied one coordinate at a time. Nothing new — except one practical question that trips up almost everyone: how big should h be?

Never use an absolute perturbation

A fixed h = 0.001 is meaningless when your inputs are a diameter of 0.3 m, a Young's modulus of 2×1011 Pa, and a Poisson ratio of 0.3. On the modulus it is an insultingly small nudge lost entirely to round-off; on the Poisson ratio it is a third of a percent.

Always scale the perturbation to the variable: h = max(abs(x_j), 1.0) * 1e-6 for a smooth analytical model, or 1 % of the value when the model is noisy or you want a finite-change engineering sensitivity rather than a mathematical one.

3. Building the sensitivity engine

Step 1 — one partial derivative

import numpy as np

def partial(func, params, key, rel_h=1e-6):
    """Centred-difference partial derivative of func with respect to params[key].

    func   : callable taking a dict of parameters, returning a float
    params : dict of parameter values
    key    : which parameter to perturb
    rel_h  : perturbation as a fraction of the parameter's own magnitude
    """
    x = params[key]
    h = max(abs(x), 1.0) * rel_h      # scaled — see the trap above

    up   = dict(params); up[key]   = x + h
    down = dict(params); down[key] = x - h
    return (func(up) - func(down)) / (2 * h)

Passing parameters as a dictionary rather than positional arguments is a deliberate choice: it keeps the name attached to the number. In a report, "∂v/∂Cd" is meaningful and "the third sensitivity" is not.

Step 2 — all of them, ranked

Raw partials cannot be compared to each other — they carry different units. ∂v/∂m is in m/(s·kg); ∂v/∂A is in m/(s·m²). Comparing them is comparing kilograms to square metres. The fix is to make the sensitivity dimensionless:

Sj = ∂f∂xj · xjf the elasticity

Read it out loud: a one percent change in xj produces an Sj percent change in f. Now every input is on the same scale and ranking is honest.

def sensitivity_table(func, params, rel_h=1e-6):
    """Return a list of (name, value, dfdx, S) sorted by |S| descending."""
    f0 = func(params)
    rows = []
    for key, val in params.items():
        d = partial(func, params, key, rel_h)
        S = d * val / f0 if f0 != 0 else float('nan')
        rows.append((key, val, d, S))
    return sorted(rows, key=lambda r: -abs(r[3]))

Step 3 — the pump station, settled

Darcy–Weisbach head loss:

hL = f LD V22g   with   V = 4QπD2 
def head_loss(p):
    V = 4*p['Q'] / (np.pi * p['D']**2)
    return p['f'] * p['L'] / p['D'] * V**2 / (2 * p['g'])

params = {'f': 0.022, 'L': 450.0, 'D': 0.30, 'Q': 0.085, 'g': 9.81}

print(f"h_L = {head_loss(params):.4f} m")
for name, val, d, S in sensitivity_table(head_loss, params):
    print(f"{name:>3}  value={val:12.5g}  dh/dx={d:14.5g}  S={S:+7.3f}")

Read the exponents straight off the physics

The dimensionless sensitivities came out as clean integers: −5, +2, +1, +1. That is not a coincidence. Substituting V gives hL ∝ fLQ2D−5, and for a pure power law the dimensionless sensitivity is exactly the exponent.

Use this as your correctness check: whenever your model is a product of powers, your numerical sensitivities must reproduce the exponents. If they do not, your perturbation size is wrong or your code has a bug. This one check catches most Lab 02 errors before they reach the report.

The argument in the design review is now over. Diameter is five times more damaging than length, per percent. Send the crew with the calipers.

4. From sensitivity to an error bar

Knowing which input matters is step one. The client wants a number with a tolerance on it. If each input xj has uncertainty Δxj, the first-order Taylor expansion (which you will derive properly in Lab 09) gives two answers:

worst case:  Δf = ∑j |∂f/∂xj| Δxj       statistical:  σf = √ ∑j (∂f/∂xj)2 σj2 
def propagate(func, params, uncertainties):
    """Return (worst_case, rss) uncertainty in func given per-parameter uncertainties."""
    worst = 0.0
    sumsq = 0.0
    for key, u in uncertainties.items():
        d = partial(func, params, key)
        worst += abs(d) * u
        sumsq += (d * u)**2
    return worst, np.sqrt(sumsq)

u = {'f': 0.004, 'L': 5.0, 'D': 0.005, 'Q': 0.003}
worst, rss = propagate(head_loss, params, u)
print(f"h_L = {head_loss(params):.3f} +/- {rss:.3f} m (rss), +/- {worst:.3f} m (worst case)")
Which one do you report?

Worst case assumes every error conspires against you simultaneously. Use it for safety factors and code compliance — it is deliberately pessimistic.

Root-sum-square assumes the errors are independent and random, so some cancel. Use it for realistic performance estimates and instrument specifications. It is typically 40–60 % smaller.

Reporting one without saying which is a quiet way of misleading your reader.

5. Where it breaks

Sensitivity is local

Every number above is valid at that operating point. Double the flow and the friction factor itself changes with Reynolds number, and your neat −5 exponent no longer holds. Always report the operating point alongside the sensitivity.

Large uncertainties break linearity

The propagation formulas keep only the first Taylor term. If ΔCd is ±30 %, "small perturbation" is a fiction. Check by evaluating the model at the extremes and comparing to the linear prediction.

Interactions are invisible

One-at-a-time perturbation cannot see that D and Q matter jointly through V. For strongly coupled models you need a Monte Carlo or a global sensitivity method.

Round-off in the perturbation

Make rel_h too small — 10−14, say — and subtractive cancellation returns with a vengeance. The V-curve of Lab 01 is still governing you. Sweep it and see.

The honest check: Monte Carlo

def monte_carlo(func, params, sigmas, n=20000, seed=0):
    """Sample every parameter from a normal distribution and report the spread."""
    rng = np.random.default_rng(seed)
    out = np.empty(n)
    for i in range(n):
        trial = {k: (v + rng.normal(0, sigmas.get(k, 0.0))) for k, v in params.items()}
        out[i] = func(trial)
    return out.mean(), out.std()

Run it against your root-sum-square number. For mild uncertainties they agree to two or three figures, and that agreement is your evidence that the linear analysis was legitimate. When they disagree, the linear analysis is the one that is wrong — and you have just discovered your model is nonlinear over the range that matters.

7. What to carry into Lab 03

  • A partial derivative is a centred difference with everything else frozen.
  • Scale the perturbation to the variable; never use a fixed absolute h.
  • Dimensionless sensitivity = percent-in, percent-out. For power laws it equals the exponent — use that as your check.
  • Worst-case and RSS answer different questions; say which you used.
