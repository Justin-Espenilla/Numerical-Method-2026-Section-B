Gradient Descent — Following the Derivative Downhill

In Lab 02 you computed derivatives and reported them. Now you will act on them. The gradient points uphill; step the other way, repeat, and you have the algorithm that fits curves to data, trains neural networks, and sizes optimal designs — all from the same finite difference you wrote in Lab 01.

1. The story: the hiker in the fog

The oldest explanation in optimisation, and still the best

You are on a mountainside in fog so thick you can see one metre in any direction. You must reach the valley floor. You cannot see the valley. You cannot see the summit. You can only feel the ground under your boots.

So you feel which way is steepest downhill, take a step that way, and repeat. If the fog never lifts and the mountain has only one valley, you will get there.

That is the entire algorithm. Everything else in this lab is about two questions the hiker faces every step: which way is down, and how big a step should I take?

Why an engineer cares

"Find the minimum" is the same sentence as: find the member size that minimises weight; find the operating point that minimises energy cost; find the model coefficients that minimise disagreement with your measured data. That last one — curve fitting — is the case you will meet most often, and it is the case in Lab 08 and in your thesis.

2. The gradient

For a function of several variables, the gradient is simply the column of all partial derivatives — the vector you already know how to compute:

∇f(x) = [ ∂f/∂x1, ∂f/∂x2, …, ∂f/∂xn ]T

Two facts about it, both worth stating out loud because they are what make the method work:

  1. ∇f points in the direction of steepest increase. So −∇f is the steepest way down — the direction the hiker's boots detect.
  2. Its magnitude |∇f| is how steep that is. At a minimum the ground is flat, so ∇f = 0. That is both our target and our stopping test.
import numpy as np

def gradient(func, x, rel_h=1e-6):
    """Numerical gradient by centred differences, one coordinate at a time.

    func : callable taking a 1-D array, returning a float
    x    : 1-D array, the point at which to evaluate
    """
    x = np.asarray(x, float)
    g = np.zeros_like(x)
    for j in range(x.size):
        h = max(abs(x[j]), 1.0) * rel_h     # scaled, as in Lab 02
        up, down = x.copy(), x.copy()
        up[j]   += h
        down[j] -= h
        g[j] = (func(up) - func(down)) / (2*h)
    return g

Count the cost: 2n function evaluations per gradient. For five design variables that is ten evaluations per step, and a thousand steps is ten thousand evaluations. If each evaluation is a finite-element run, you have just committed to a week of computing. Remember this number — it is why analytical gradients are worth deriving when you can.

3. The algorithm

xk+1 = xk − α ∇f(xk) α = step size / learning rate 
def gradient_descent(func, x0, alpha=0.01, tol=1e-6, max_iter=10000):
    """Minimise func starting from x0 by fixed-step gradient descent.

    Returns (x_best, f_best, n_iter, history)
    history is a list of (k, x, f, |grad|) for plotting the path.
    """
    x = np.asarray(x0, float).copy()
    history = []

    for k in range(max_iter):
        g  = gradient(func, x)
        gn = np.linalg.norm(g)
        history.append((k, x.copy(), func(x), gn))

        if gn < tol:                       # the ground is flat: we have arrived
            break

        x = x - alpha * g                   # the step

        if not np.all(np.isfinite(x)):        # diverged to infinity
            raise RuntimeError(f"Diverged at iteration {k}. Reduce alpha.")

    return x, func(x), k, history
Three stopping tests, and why we chose this one

|∇f| < tol — the ground is flat. This is the mathematically honest test and the one we use.

|xk+1 − xk| < tol — we stopped moving. Dangerous on its own: a tiny α also stops you moving, and you will declare victory halfway up the slope.

|fk+1 − fk| < tol — the value stopped improving. Useful in practice, but on a long flat valley floor it triggers early.

Production code checks all three, and also caps the iterations. Ours checks the gradient and caps the iterations.

4. Watch it work — and watch it fail

Start with a bowl, the easiest possible landscape:

def bowl(x):
    return (x[0] - 3)**2 + 2*(x[1] + 1)**2      # minimum at (3, -1), f = 0

for alpha in (0.01, 0.1, 0.4, 0.6):
    try:
        x, f, k, _ = gradient_descent(bowl, [0.0, 0.0], alpha=alpha)
        print(f"alpha={alpha:5.2f}  x=({x[0]:8.5f},{x[1]:9.5f})  f={f:.3e}  iters={k}")
    except RuntimeError as e:
        print(f"alpha={alpha:5.2f}  {e}")

The stability limit is not a mystery

For a quadratic, gradient descent converges only when α < 2/λmax, where λmax is the largest eigenvalue of the Hessian. Our bowl has Hessian diag(2, 4), so λmax = 4 and the limit is α < 0.5. That is exactly where the table breaks. You will verify this number yourself in the assignment — and in Lab 07 you will learn what eigenvalues are doing in a matrix in the first place.

The narrow valley — where descent earns its bad reputation

def rosenbrock(x):
    """The banana function. Minimum at (1, 1), f = 0. Notoriously hard."""
    return (1 - x[0])**2 + 100*(x[1] - x[0]**2)**2

Run plain descent on this from (−1.2, 1) and it will take tens of thousands of iterations, or stall entirely. The reason is worth understanding, because it recurs everywhere: the function forms a long, curved, extremely narrow valley. The gradient points almost perpendicular to the valley floor, so the iterates zigzag across the valley while creeping along it. Almost all your effort goes sideways.

Plot the path over a contour map and the zigzag is unmistakable:

import matplotlib.pyplot as plt

X, Y = np.meshgrid(np.linspace(-2, 2, 400), np.linspace(-1, 3, 400))
Z = (1 - X)**2 + 100*(Y - X**2)**2
plt.contour(X, Y, Z, levels=np.logspace(-1, 3.5, 25))

5. Three fixes, in increasing order of cleverness

Fix 1 — backtracking line search: stop guessing α

Instead of a fixed step, try a big one; if the function did not actually decrease enough, halve it and try again. This single change removes the most fragile parameter in the algorithm.

def backtracking(func, x, g, alpha0=1.0, rho=0.5, c=1e-4, max_halvings=50):
    """Armijo backtracking: shrink alpha until f decreases sufficiently."""
    f0 = func(x)
    gg = g @ g
    alpha = alpha0
    for _ in range(max_halvings):
        if func(x - alpha*g) <= f0 - c*alpha*gg:    # the Armijo condition
            return alpha
        alpha *= rho
    return alpha

Read the Armijo condition as a contract: "I will accept this step only if it delivers at least a small fraction c of the decrease that the slope promised." It refuses steps that overshoot and it refuses steps that barely move.

Fix 2 — momentum: remember where you were going

v = np.zeros_like(x)
for k in range(max_iter):
    g = gradient(func, x)
    v = beta*v + g            # beta ~ 0.9: a running average of past gradients
    x = x - alpha*v

The sideways components of the zigzag alternate in sign and cancel in the running average; the along-valley component always points the same way and accumulates. The hiker stops staggering left and right and starts striding down the valley. This is the idea underneath every optimiser in modern machine learning.

Fix 3 — scale your variables

The fix nobody teaches and everybody needs

If x1 is a length in metres (~0.3) and x2 is a modulus in pascals (~2×1011), your landscape is not a bowl — it is a canyon 1012 times longer than it is wide, and no single step size works for both. Rescale each variable by its nominal magnitude so all of them live near 1, optimise in the scaled space, then convert back. This usually turns an impossible problem into an easy one, and it costs four lines.

6. The real application: fitting a model to data

Case file — materials lab, creep test

A student has 40 measurements of strain against time and a model, ε(t) = a(1 − e−t/b). She needs a and b. The model is nonlinear in b, so there is no formula to solve. There is only a landscape.

Define the disagreement between model and data — the sum of squared residuals — and minimise it. The parameters become the coordinates:

def make_sse(t, eps):
    """Return an SSE function of the parameter vector p = [a, b]."""
    def sse(p):
        a, b = p
        model = a * (1 - np.exp(-t / b))
        return np.sum((eps - model)**2)
    return sse

sse = make_sse(t_data, eps_data)
p, f, k, hist = gradient_descent(sse, [1.0, 1.0], alpha=1e-3)
print(f"a = {p[0]:.4f}, b = {p[1]:.4f}, SSE = {f:.5e}, iterations = {k}")

This is the bridge between three labs: the derivative gives the direction (Lab 01), the sensitivity tells you which parameter the data actually constrains (Lab 02), and the minimum gives the fit. When the model is linear in its parameters, Lab 07 will solve exactly this problem in one shot with a matrix — no iteration at all. Knowing when you are allowed to do that is worth a great deal of computer time.

7. Where it breaks

Local minima

The hiker finds a valley, not the valley. Always restart from several initial guesses and compare. If they disagree, your landscape is not convex and you must report that.

Badly scaled variables

Mixed units make the landscape a canyon. Symptom: it converges in one variable and completely ignores the other. Fix by rescaling, not by shrinking α.

Noisy or discontinuous f

If f comes from a simulation with its own tolerance, the numerical gradient is noise divided by a small number — Lab 01's amplification problem again. Use a larger perturbation, or a derivative-free method.

Cost

2n evaluations per iteration × thousands of iterations. Before you optimise, ask whether an analytical gradient exists. It usually does, and it is usually 50× faster.

9. What to carry into Lab 04

  • The gradient is a vector of partial derivatives; minus it points downhill.
  • Step size is the whole game: too small wastes time, too large diverges, and the limit is set by curvature.
  • Zigzagging means a narrow valley; fix it with momentum or by rescaling variables.
  • Curve fitting is minimisation with the parameters as coordinates.
