Lab Lecture 4 · Lecture topic: Physical Meaning of the Integral

The Integral as Accumulation

A derivative tells you how fast something is changing. An integral tells you how much has piled up. In the field you will almost never be handed a function to antidifferentiate — you will be handed a logger file and asked for a total. This lab turns "area under the curve" into working code with a stated error.

1. The story: the storm that was under-designed

Case file — municipal drainage, post-flood review

A tipping-bucket rain gauge recorded a storm at five-minute intervals for six hours. The design office needs the total rainfall depth to check the detention basin. Somebody has already reported it: they took the average of the first and last intensity readings and multiplied by six hours.

That figure is 8 mm. The basin overflowed as though it had received four times as much.

The intensity was not constant. It rose sharply, peaked at the height of the storm, and tailed off. The intensity record is a hump, and a straight line between its two ends passes nowhere near it.

The physical meaning, stated once

If i(t) is a rate, then ∫i dt is the total accumulated. Millimetres per hour integrated over hours gives millimetres of rainfall. The same sentence covers runoff volume from discharge, settlement from strain rate, charge from current, distance from speed, and work from power. The units always tell you what you computed — multiply the units of the y-axis by the units of the x-axis.

2. From the Riemann sum to something useful

Lecture defined the integral as a limit of rectangles. Delete the limit — as we did with the derivative — and you have a method. But the shape you use to fill each strip matters enormously.

Rectangles: correct, and bad

import numpy as np

def left_rect(f, a, b, n):
    """Left Riemann sum with n strips. Error O(h) — first order."""
    h = (b - a) / n
    x = a + h*np.arange(n)          # left edge of every strip
    return h * np.sum(f(x))

Try it on ∫01 ex dx = 1.71828… With n = 10 you get about 1.6338 — a 4.9 % error. Double n and the error roughly halves. To get four decimal places you would need tens of thousands of strips. The rectangle wastes information: it uses the height at one edge and ignores the other.

Trapezoids: use both ends

I ≈ h2 [ f0 + 2f1 + 2f2 + … + 2fn−1 + fn ] O(h2) 
def trapezoid(f, a, b, n):
    """Composite trapezoidal rule with n strips. Error O(h**2)."""
    h = (b - a) / n
    x = np.linspace(a, b, n + 1)
    y = f(x)
    return h * (y[0]/2 + y[1:-1].sum() + y[-1]/2)
Why the interior points count twice

Every interior point is the right edge of one trapezoid and the left edge of the next, so it appears in two strips. The two endpoints belong to one strip each. That is the whole meaning of the 1-2-2-…-2-1 pattern — it is not a formula to memorise, it is a count of how many trapezoids touch each sample.

Same integral, n = 10: error drops to about 0.14 %. Thirty-five times better than rectangles for exactly the same number of function evaluations.

Simpson's rule: fit a parabola instead of a line

A straight line through two points is a poor model of a curve. A parabola through three points is much better — and costs nothing extra, because you already have those three points.

I ≈ h3 [ f0 + 4f1 + 2f2 + 4f3 + … + 4fn−1 + fn ] O(h4) 
def simpson(f, a, b, n):
    """Composite Simpson's 1/3 rule. n MUST be even. Error O(h**4)."""
    if n % 2 != 0:
        raise ValueError("Simpson's 1/3 rule needs an even number of strips.")
    h = (b - a) / n
    x = np.linspace(a, b, n + 1)
    y = f(x)
    return h/3 * (y[0] + 4*y[1:-1:2].sum() + 2*y[2:-1:2].sum() + y[-1])

Same integral, n = 10: relative error about 1×10−6. Compare the three at a glance:

Three methods, identical cost in function evaluations, five orders of magnitude apart in accuracy. The difference is entirely in what shape you assume the function has between your samples. Every integration rule you will ever meet is that same choice, made more or less cleverly.

3. Verify the order — do not take my word for it

The error-halving column above is a testable claim. Test it:

def order_study(method, f, a, b, exact, ns=(4, 8, 16, 32, 64, 128)):
    """Print error and the ratio between consecutive errors."""
    prev = None
    print(f"{'n':>6} {'estimate':>18} {'|error|':>12} {'ratio':>8}")
    for n in ns:
        est = method(f, a, b, n)
        err = abs(est - exact)
        ratio = prev/err if prev else float('nan')
        print(f"{n:6d} {est:18.12f} {err:12.3e} {ratio:8.2f}")
        prev = err

order_study(trapezoid, np.exp, 0, 1, np.e - 1)
order_study(simpson,   np.exp, 0, 1, np.e - 1)

The ratio column should march to 4.00 for the trapezoid and 16.00 for Simpson. If you get 2.00 where you expected 4.00, you have a bug — most likely a wrong h or an off-by-one in the endpoints. This ratio test is the single most reliable debugging tool in numerical methods, and it needs no knowledge of the right answer beyond one reference value.

When the ratio suddenly collapses

Push n to 106 and Simpson's ratio stops being 16 and starts wandering. You have hit the round-off floor from Lab 01 — you are now adding a million numbers, each with its own tiny representation error, and the accumulated noise exceeds the truncation error you were trying to remove. The V-curve is back. There is a best n, and more is not better.

4. Integrating data instead of functions

Back to the storm. There is no i(t) — there are 72 numbers. The trapezoidal rule does not care: it only ever used the samples.

def trapz_data(x, y):
    """Trapezoidal rule for tabulated data. Handles unequal spacing."""
    x, y = np.asarray(x, float), np.asarray(y, float)
    dx = np.diff(x)
    return np.sum(dx * (y[:-1] + y[1:]) / 2)

Notice this version needs no constant h at all — each strip carries its own width. That matters more than it sounds: field data is full of gaps where the logger dropped a sample, and a rule that assumes even spacing will silently return the wrong total.

The cumulative integral: the answer at every instant

Often the total is less interesting than the running total — fuel burnt by hour 6, rainfall accumulated by 3 p.m., charge delivered so far.

def cumulative_trapz(x, y):
    """Running integral. Returns an array the same length as x, starting at 0."""
    dx = np.diff(x)
    strips = dx * (y[:-1] + y[1:]) / 2
    return np.concatenate(([0.0], np.cumsum(strips)))

Plot the rate and its running total on the same time axis, and the relationship from lecture becomes visual: the accumulation curve is steepest where the rate is highest, and flat where the rate is zero. Differentiating the accumulation curve with your Lab 01 code returns the original rate — the fundamental theorem of calculus, demonstrated numerically in two lines.

Simpson on data, and the odd-count problem

Simpson's 1/3 rule consumes points in pairs of strips, so it needs an even number of strips — an odd number of samples. Real data does not consult you about this. Three honest options:

  1. Apply Simpson 1/3 to the first n−1 strips and the trapezoid to the last one. Simple, and it degrades only the final strip.
  2. Apply Simpson's 3/8 rule (which uses three strips) to the last three and 1/3 to the rest. Keeps fourth-order accuracy throughout.
  3. Drop a data point. Never do this without saying so in the report.

5. Where it breaks

Kinks and discontinuities

Simpson fits a parabola through three points. If a valve slammed shut between two samples, no parabola describes that, and fourth-order accuracy evaporates. Integrate each smooth segment separately and add.

Too few samples

The rules interpolate between your data. If the true curve wiggles between samples, no method can know. Accuracy is limited by sampling rate, not by cleverness — this is the integration counterpart of Nyquist.

Infinite or singular integrands

∫01dx/√x is finite, but f(0) is infinite and your code returns inf. Needs a substitution or an open rule that never evaluates the endpoint.

Round-off at enormous n

Millions of strips accumulate representation error. Use math.fsum for compensated summation, or better, use a higher-order rule with fewer strips.

Integration is forgiving where differentiation is brutal

Lab 01 showed that noise destroys derivatives, because you divide small differences by a small h. Integration does the opposite: it averages, and random noise partly cancels over the sum. Integrating a noisy signal is one of the safest things you can do to it. Remember this asymmetry — when you have a choice between a formulation that differentiates data and one that integrates it, integrate.

7. What to carry into Lab 05

  • An integral of a rate is a total; the units prove what you computed.
  • The rule you pick is a statement about the shape between samples: flat, straight, or parabolic.
  • The error-ratio test (2, 4, 16) verifies your implementation without needing an exact answer.
  • Data-driven integration needs no formula and tolerates unequal spacing.
  • Integration suppresses noise; differentiation amplifies it.
