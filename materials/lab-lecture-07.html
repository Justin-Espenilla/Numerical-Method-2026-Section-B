Many Load Cases, and Matrices Too Large to Eliminate

Gauss elimination solves one system once. Structural practice asks for the same structure under dozens of load combinations, and seepage or pipe-network models produce matrices with a million entries of which 99.9 % are zero. This lab covers LU factorisation, the Gauss–Seidel iteration, and the condition number that tells you whether to believe any of it.

1. The problem with solving twice

Case file — design office, load combinations

A frame has been modelled and its stiffness matrix assembled. The code requires the structure to be checked under dead load, live load, wind from four directions, seismic in two directions, and the factored combinations of all of them: thirty-one load cases in total.

The geometry does not change between cases. Only the right-hand side does. Running the full elimination thirty-one times repeats the same n3/3 arithmetic thirty-one times on identical numbers.

The observation that saves the day

Forward elimination touches only [A]. The right-hand side is carried along, but it never affects which multipliers are used. So do the expensive part once, store the multipliers, and reuse them for every new {b}. That is LU factorisation.

2. LU factorisation

Elimination factors the matrix into a lower triangular [L] holding the multipliers, and an upper triangular [U] holding the eliminated system:

[A] = [L][U]   ⇒   [L][U]{x} = {b}

Solving then splits into two triangular solves, each costing only n2/2:

  1. Forward substitution: solve [L]{d} = {b} for the intermediate vector {d}.
  2. Back substitution: solve [U]{x} = {d}.
import numpy as np

def lu_decompose(A):
    """Doolittle LU factorisation with partial pivoting.

    Returns (LU, piv) where LU holds L below the diagonal (unit diagonal implied)
    and U on and above it; piv is the row permutation applied.
    """
    A = np.array(A, float)
    n = A.shape[0]
    piv = np.arange(n)

    for k in range(n - 1):
        p = k + int(np.argmax(np.abs(A[k:, k])))
        if p != k:
            A[[k, p]] = A[[p, k]]
            piv[[k, p]] = piv[[p, k]]
        for i in range(k + 1, n):
            A[i, k] /= A[k, k]                # store the multiplier in place of the zero
            A[i, k+1:] -= A[i, k] * A[k, k+1:]
    return A, piv


def lu_solve(LU, piv, b):
    """Solve using a stored factorisation. Cost n^2, not n^3."""
    n = LU.shape[0]
    d = np.array(b, float)[piv]

    for i in range(1, n):                    # forward substitution
        d[i] -= LU[i, :i] @ d[:i]

    x = np.zeros(n)
    for i in range(n - 1, -1, -1):        # back substitution
        x[i] = (d[i] - LU[i, i+1:] @ x[i+1:]) / LU[i, i]
    return x

The multipliers are stored in the space the zeros would have occupied, so the factorisation needs no extra memory. For thirty-one load cases on a 400-degree-of-freedom frame the saving is roughly a factor of thirty in runtime. On a 5,000-degree-of-freedom model it is the difference between a coffee break and an afternoon.

3. When the matrix is too large to factor

Case file — seepage under a sheet-pile wall

A two-dimensional seepage analysis on a 200 × 100 finite-difference grid has 20,000 unknown heads. The coefficient matrix is 20,000 × 20,000 — four hundred million entries, of which fewer than 100,000 are non-zero, because each node is connected only to its four neighbours.

Storing it densely requires 3.2 GB. Factoring it requires 2.7×1012 operations. Neither is necessary, because the equations have a structure elimination throws away.

Iterative methods never form the matrix at all. Rearrange equation i to make xi the subject, guess all the unknowns, and sweep repeatedly until the values stop changing:

xi = bi − ∑j≠i aijxj aii 
def gauss_seidel(A, b, x0=None, tol=1e-8, max_iter=10000):
    """Gauss-Seidel iteration. Returns (x, iterations, history of max |ea|)."""
    A = np.asarray(A, float)
    b = np.asarray(b, float)
    n = len(b)
    x = np.zeros(n) if x0 is None else np.array(x0, float)
    history = []

    for it in range(1, max_iter + 1):
        x_old = x.copy()
        for i in range(n):
            s = A[i, :i] @ x[:i] + A[i, i+1:] @ x[i+1:]
            x[i] = (b[i] - s) / A[i, i]       # uses updated values immediately
        ea = np.max(np.abs(x - x_old) / np.maximum(np.abs(x), 1e-30))
        history.append(ea)
        if ea < tol:
            return x, it, history
    return x, max_iter, history
Jacobi versus Gauss–Seidel

The Jacobi method computes a whole new vector from the old one. Gauss–Seidel uses each updated value immediately, within the same sweep. The change is one line and it typically halves the number of iterations. Jacobi's only advantage is that its sweeps are independent, which matters on parallel hardware and nowhere else in this course.

Will it converge?

Not always. The sufficient condition is diagonal dominance:

|aii| ≥ ∑j≠i |aij|   for every row, strict in at least one

This is not an arbitrary algebraic requirement. It says each unknown is influenced most strongly by its own equation. Physical systems in which an effect is dominated by its local cause — seepage, heat conduction, pipe networks, consolidation — produce diagonally dominant matrices as a matter of course. Structural stiffness matrices assembled without care often do not, and Gauss–Seidel then diverges no matter how good the initial guess.

def is_diagonally_dominant(A):
    A = np.abs(np.asarray(A, float))
    diag = np.diag(A)
    off  = A.sum(axis=1) - diag
    return np.all(diag >= off) and np.any(diag > off)

Check it before iterating. If it fails, reorder the equations — often the same equations in a different order are dominant — and if reordering cannot fix it, use elimination instead.

4. Relaxation

Gauss–Seidel can be accelerated by over-correcting each update:

xinew = λ xiGS + (1 − λ) xiold

With 1 < λ < 2 this is successive over-relaxation, and on a large seepage grid a well-chosen λ can cut the iteration count by an order of magnitude. With λ < 1 it is under-relaxation, which sacrifices speed to stabilise a system that would otherwise oscillate. The optimum λ depends on the matrix and is normally found by experiment — which is exactly what the assignment asks you to do.

6. The condition number

Case file — survey adjustment, two nearly parallel sight lines

A position is fixed by intersecting two bearings. When the lines cross at a healthy angle, a small error in either bearing moves the fix by a small amount. When they are nearly parallel, the same small error moves the fix by tens of metres. The geometry, not the instrument, is the problem.

The same effect appears in every linear system. The condition number measures it:

cond([A]) = ‖A‖ · ‖A−1‖   ⇒   ‖Δx‖‖x‖ ≤ cond([A]) · ‖Δb‖‖b‖
The rule of thumb worth memorising

If cond([A]) ≈ 10k, you can lose up to k significant figures in the solution. Double precision carries about 16. A condition number of 1012 therefore leaves four — and a condition number of 1016 leaves nothing at all, whatever the residual says.

c = np.linalg.cond(A)
print(f"cond(A) = {c:.3e}  -> up to {np.log10(c):.1f} significant figures lost")

This resolves the paradox from Lab 6. A small residual means the computed answer nearly satisfies the equations. In an ill-conditioned system, a vector can nearly satisfy the equations and still be far from the true solution, because the equations themselves barely distinguish between the two. Residual measures whether you solved the system; the condition number measures whether the system was worth solving.

8. Where it breaks

Iteration that will not converge

Not diagonally dominant. Symptom: the residual grows steadily. Reorder the equations first; if that fails, the method is wrong for the matrix.

Stopping too early

A small change between sweeps is not proof of convergence — a slowly converging iteration also changes slowly. Check the residual as well as the change.

Ill-conditioning mistaken for a coding error

Two solvers disagree in the sixth figure, and hours are spent hunting a bug that does not exist. Compute the condition number before debugging.

Unscaled equations

Mixing newtons with millimetres inflates the condition number artificially. Scaling rows and columns to comparable magnitude can improve conditioning by several orders.
